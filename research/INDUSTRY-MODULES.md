# Industry-Specific Research Modules

Apply these overlays only where relevant.

| Product type | Priority research |
|---|---|
| SaaS | Multi-tenancy, provisioning, integrations, reliability, contracts |
| Mobile apps | Battery, offline behavior, device fragmentation, store policies |
| Browser extensions | Permissions, security, browser compatibility, store reviews |
| AI agents | Model evaluation, action permissions, prompt injection, recovery |
| Developer APIs | SDKs, versioning, rate limits, developer experience |
| Marketplaces | Liquidity, matching, fraud, incentives, disputes |
| E-commerce | Inventory, discovery, payments, fulfillment, returns |
| Fintech | Transaction integrity, reconciliation, regulation, fraud |
| Healthcare | Clinical evidence, patient safety, medical regulation |
| Consumer electronics | Durability, battery safety, thermal design, repair |
| Automotive / EV | Functional safety, charging, battery life, diagnostics |
| Robotics | Sensors, control, autonomy, physical safety |
| Biotechnology | Laboratory validity, biosafety, regulation |
| Food and agriculture | Safety, shelf life, traceability, field conditions |
| Edtech | Learning outcomes, assessment, accessibility |
| Gaming | Balance, fairness, retention, monetization |
| Social platforms | Network effects, moderation, privacy, reputation |
| Climate and energy | Efficiency, lifecycle impact, grid compatibility |
| Industrial products | Production yield, maintenance, integration, safety |
| Public sector | Procurement, accessibility, accountability, interoperability |

## Selection rules

1. Identify product type, customer, geography, maturity, and risk.
2. Select applicable modules and any relevant combinations.
3. Identify additional industry standards and legal requirements from authoritative sources.
4. Prioritize safety-critical and decision-critical unknowns.
5. Do not assume this list replaces domain experts or formal certification.
